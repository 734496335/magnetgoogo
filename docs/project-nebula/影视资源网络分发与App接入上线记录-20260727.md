## 三、App 消费协议

App 不使用“第一个返回即采用”的竞速方式，而是：

1. 并行读取两个 `current.json`；
2. 对每个候选执行 Ed25519 验签；
3. 检查最低 App 版本；
4. 选择 revision 最高的合法候选；
5. 同 revision 的两个候选必须具有完全相同的 pointer SHA-256，否则以 `MEDIA_POINTER_SAME_REVISION_CONFLICT` 全部拒绝；
6. 新候选不得低于设备已接受 revision，同 revision 的 pointer、release ID 或 Manifest 哈希不得漂移；
7. 验证 Manifest SHA-256 与签名；
8. 频道列表仅下载 Catalog 对象；
9. 点击条目后才下载 Detail 和 Resources 对象；
10. 每个对象都校验大小和 SHA-256；
11. 当前端点失败时，只能在同一 release 内切换另一个数据面。

App 内置公钥，不包含私钥。私钥只保存在本地 Git 忽略目录和离线备份中。

## 四、缓存和回退

加载顺序：

```text
内存 → AES 磁盘缓存 → APK bundled Feed
```

磁盘缓存：

- AES-256-CBC 加密
- HMAC-SHA256 完整性校验
- 随机设备密钥保存在 SecureStore
- 最长有效期 72 小时
- 主缓存 `media.cache.enc.json` 与备份 `media.cache.backup.enc.json`
- 新密文先写临时文件并解密回读，再把旧主缓存原子移动为 backup，最后安装新主缓存
- 缓存持久化 pointer revision、pointer SHA-256、release ID 和 Manifest SHA-256，用于跨重启防回滚
- 主缓存损坏时自动从 backup 恢复并重建主缓存
- 主备同时篡改、解密失败或过期时删除缓存并回退 bundled Feed

## 七、回滚

### 数据回滚

不修改历史不可变对象。需要回滚时：

1. 选择已签名、revision 更高的回滚指针；
2. 指向上一份已验证 Manifest；
3. 两个数据面完成预检后再双端点发布 `current.json`；
4. 禁止使用更低 revision 覆盖线上指针。

### App 回退

- 网络不可用：自动使用 72 小时内 AES 缓存
- 缓存不可用：自动使用 APK bundled Feed
- 不需要服务器在线代理即可保留基本资源页体验
