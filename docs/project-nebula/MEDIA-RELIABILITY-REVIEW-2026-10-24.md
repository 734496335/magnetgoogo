## 结论

确实存在重复的工程失误。最明确的是发布清单容量：2026-07-30 的提交已把 Python bridge 与 Cloudflare Worker 的 manifest 上限从统一 1 MiB 改为独立 2 MiB，本次又超过 2 MiB。旧修复有边界测试，但缺少随真实数据增长执行的容量预警，且上传前没有对两个目标的整个计划进行容量检查。

另一方面，多天重复报错不等于每天出现新 bug。阿里云现存收据记录，2026-10-18 至 10-24 有 27 次同样的 manifest 超限失败，R2 阶段累计耗时 21.39 小时。这是同一事故没有解决、定时任务不断重试。旧媒体告警状态停在 09-10，当前 compute/finalizer 调度又未接入旧接线，使故障持续而没有通过该链路及时通知用户。

并非所有旧修复都无效。10-05 的真实无人值守 Oracle compute → 阿里云 finalizer 周期有成功状态、同一 handoff、revision54→55 和双端 SHA 证据。SixV 状态机和最终封面过滤计数的问题当时已经修复；本次实际原 finalizer 镜像仍包含正确 cover audit，不能把它说成本次又复发。

## 反复问题背后的共同原因

### 1. 修复了当下的数值，没有持续观察增长

原大小测试证明代码正确执行2 MiB合同，也会正确拒绝超过2 MiB的清单。它没有证明生产数据永远不会超过该值。容量检查需要使用真实清单和实际部署上限持续运行，并在达到硬上限前通知。

### 2. 跨阶段、跨时间的语义覆盖不足

正常单次抓取无法覆盖：成功后的最小间隔跳过、暂时HTTP错误后来变成404、旧fallback先过期而恢复尚未执行、封面过滤导致最终计数变少。它们都是整体管线需要处理的状态转换。回归测试应保留这些具体场景，而不仅是验证某个修复分支。

### 3. 代码、定时器和实际生产执行结果曾被混用

定时器active只证明会调度；源码测试通过只证明候选代码；两端仍为同一旧revision只证明一致，不能证明持续更新。Oracle、阿里云、Worker及公开读面必须使用同一个run/包SHA/revision/manifest SHA贯通验收。

### 4. 永久规则没有全部变成持续执行的检查

BL-064已经提出连续失败和last-success告警，但10-24仍查到当前unit缺接线。问题不在于完全没有复盘文字，而在于规则没有完整成为覆盖当前实际部署的运行机制。迁移和升级必须同时验证业务、检查、事故状态及通知回执。

## 本轮已落实的防复发措施

1. **发布之前检查两个目标的整个计划**，读取Worker声明的真实能力并严格校验；客户端和远端限制共同生效，部分升级不假定兼容。确定的超限不会等大量对象上传后才暴露。
2. **manifest有界扩到8 MiB**，普通对象仍1 MiB，current仍64 KiB；鉴权、摘要、不可变对象、质量和时效门禁保留。真实2.47 MB清单、精确8 MiB边界已线上上传并读回验证；测试对象已清理。
3. **80%容量微信预警**已部署到阿里云现有一分钟巡检。读取当前公开manifest大小，以及本机实际部署Python发布源的上限常量；没有新增手工维护的上限数字或复制凭据。预警只描述本机发布客户端容量，远端能力仍由发布前预检负责。
4. **容量未知不会假恢复**。源码常量无法解析、文件缺失、非法路径、符号链接越界只产生独立检查异常，不清除既有发布或容量事故；读取使用AST，不执行发布源代码。
5. **当前调度已接微信**。compute/finalizer任务状态和完成记录由各自主机watchdog观察；P0真实故障已取得provider confirmed回执。当前任务运行中保持pending，成功发布后才产生真实恢复事件。
6. **实际执行体核对**。本轮核验Oracle计算包两端SHA相同、阿里云实际镜像ID与持久配置一致；新旧最终质量校验函数AST相同，保留既有cover audit修复。

容量检查在Windows专项37 passed / 1 symlink skipped；实际阿里云Python3.6.8补验6项合同场景（含2项符号链接越界），真实只读观察及自然timer运行成功。另有捕获旧rev67尺寸的固定回归，证明99.57%时会提前预警。

## 后续验收边界

- 80%预警能提示逐步增长；突然大幅跳升仍可能触发预检拒绝。不会为减少报警而自动放宽质量、时效、签名或容量门禁。
- 8 MiB不是永久无限容量。接近预警线时应评估清单结构/分片和发布耗时，不应再只靠临时改常数。
- 后续部署必须继续核对host source与实际image，容量监控读取的上限才具有正确含义。
- 当前修复的主动完整生产运行与下一每日自然周期分别记录；不提前宣称后一周期已经通过。
- 资源结构和磁链字段校验不等于每条磁链已实测下载；平台确认投递不等于用户已读。
