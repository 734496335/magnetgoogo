# 影视资源上线后运营增长埋点分析（2026-08-02）

## 一、结论摘要

影视资源功能随 `v0.2.1` 于 **2026-07-28 22:47（UTC+8）**正式上线。基于阿里云运营埋点原始批次重新计算后，当前结论是：

1. **拉新和活跃显著提升**：上线后完整4天的平均DAU由105.7升至135.3，增长28.0%；日均新增设备由25.9升至46.0，增长77.6%。
2. **不是只有新增用户带动**：日均回访设备由79.8升至89.3，增长11.9%；日均启动次数由208升至307，增长47.6%。
3. **搜索仍是绝对核心价值链路**：0.2.x活跃设备中，71.4%发生过带`search_id`的磁力打开/复制；而可推断为影视详情资源动作的设备仅9.5%。搜索动作量约为影视详情资源动作的84.5倍。
4. **影视资源功能已有真实价值，但尚未形成稳定高频使用**：上线后4天共有23台设备产生46次影视详情资源动作，其中30次打开、16次复制。头部单设备仅占13%，不是单个测试机制造的假数据。
5. **影视资源动作用户可能更有留存价值**：成熟样本中，新影视资源动作用户D1为20.0%，未产生影视资源动作的新0.2.x用户D1为12.6%；但样本仅15人与103人，只能作为方向性信号。
6. **最大问题是留存而不是拉新**：上线前成熟新用户D1为22.5%，上线后7月29日至31日成熟新用户D1为11.9%，下降10.6个百分点。
7. **新增流量更国际化，但质量更不稳定**：新增设备中非中国IP占比由18.8%升至41.3%。IP可能受VPN影响，但流量结构变化明确。
8. **现有埋点不足以完整证明影视漏斗**：没有资源页曝光、卡片点击、详情打开、具体影视ID、频道、位置、revision等事件。目前只能通过0.2.x中“不带`search_id`的打开/复制”推断影视详情资源动作。
9. **当前运营后台搜索图表口径错误**：生产服务器仍只统计旧事件`search`，未计入0.2.x主要事件`search_submitted`，使新版搜索量被低估约一个数量级。本报告直接基于原始批次重算，未采用该错误汇总。

总体裁决：

`ACQUISITION=POSITIVE`

`ACTIVATION=POSITIVE_BUT_MEDIA_FUNNEL_WEAK`

`SEARCH_VALUE=STRONGLY_POSITIVE`

`RETENTION=WARNING`

`MEASUREMENT_COMPLETENESS=FAIL`

## 九、数据质量与埋点缺口

### 9.1 生产后台搜索口径错误

阿里云当前`/opt/admin-server/server.js`仍使用：

```js
searches: counts.search || 0
```

0.2.x主要上报`search_submitted`，导致后台搜索趋势图严重低估新版搜索量。例如7月29日至8月1日，后台旧口径只会看到254次旧`search`，原始批次重算后的真实搜索提交为2,590次。

需要改为：

```js
searches = (counts.search || 0) + (counts.search_submitted || 0)
```

同时应将`search_completed`单列，不与提交次数混淆。

### 9.2 影视漏斗缺失

0.2.4至少补充以下事件：

1. `resource_tab_view`
2. `media_card_click`
3. `media_detail_load_result`
4. `media_resource_open`
5. `media_resource_copy`
6. `media_feed_sync_result`

建议字段：

- `release_id`
- `media_id_hash`，不上传原始标题
- `content_kind`
- `channel`：featured/latest/updating/genre
- `position_bucket`
- `resource_count_bucket`
- `cache_hit`
- `load_ms`
- `success/error_code`

禁止上传磁力URL、完整标题和个人可识别信息。

### 9.3 拉新归因缺失

当前没有安装来源、更新入口、官网/GitHub/蓝奏云来源、公告曝光和更新完成事件，无法判断新增设备增长来自哪一条渠道。建议增加匿名的：

- `update_prompt_view`
- `update_download_start`
- `update_install_handoff`
- `first_start_version`
- `acquisition_channel`，仅使用有限枚举

## 十、运营增长建议

### P0：先修测量，不继续盲目优化UI

1. 修复运营后台搜索统计口径并用原始批次回填最近30天。
2. 在0.2.4补齐影视曝光→详情→资源动作漏斗。
3. 给影视事件绑定revision和匿名media ID，才能判断每日自动爬取是否真正创造消费。

### P1：提升影视入口激活率

当前影视资源动作设备转化只有9.5%，优先做：

1. 首页或底部资源Tab增加一次性“新功能/今日新增”提示。
2. 资源页首屏明确显示“今日更新X部、共X条资源”，强化新鲜度价值。
3. 卡片上强化可点击区域和“X个资源”行动提示，避免只浏览不进入详情。
4. 影视详情首屏展示最优1—2条资源的紧凑操作入口，完整列表继续下沉。
5. 建立搜索结果与影视详情的双向跳转，让影视页成为搜索的快捷入口，而不是孤立模块。

### P1：把新增流量转成留存

1. 增加本地收藏、最近浏览、追更列表，先不依赖账号系统。
2. 对剧集提供“有新资源”本地角标或下次启动提示。
3. 新用户首次进入资源页时只展示精品推荐和近期更新，降低信息负担。
4. 针对国际IP新用户，核对语言、下载链路、内容国家分类和影视标题显示质量。

### P2：保持搜索为核心，影视做增量

搜索仍是绝对主链路，且0.2.x搜索质量显著提升。运营策略不应把首页完全改造成影视App，而应定位为：

> 搜索解决明确需求，影视资源页解决“我不知道搜什么”和“最近有什么更新”。

影视页的核心KPI应是：

- 资源Tab渗透率
- 卡片点击率
- 详情资源动作率
- 影视用户D1/D7
- 影视用户向搜索的交叉转化
- 每个revision带来的新增消费影视数

## 十一、最终运营判断

影视资源上线已经证明三件事：

1. 能明显扩大新增用户和DAU。
2. 能产生真实资源消费，并可能提升已激活用户留存。
3. 与搜索协同，而不是替代搜索。

但也暴露两个核心问题：

1. 影视入口到资源动作的转化仍低，约9.5%。
2. 首发新增用户D1明显下降，当前增长偏“上层漏斗扩张”，还没有稳定沉淀。

下一阶段不应继续只增加影视数量，而应优先完成**影视漏斗埋点、入口激活、收藏/追更和新增用户留存闭环**。自动爬取已经解决供给问题，当前最大瓶颈已经从“有没有内容”转为“用户是否发现、消费并回来”。
