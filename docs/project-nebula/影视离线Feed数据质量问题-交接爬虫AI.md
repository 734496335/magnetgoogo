# 影视离线 Feed 数据质量问题——交接爬虫 AI

日期：2026-07-26
范围：`data/resource_index/sixv_app_bundle/feed.json`、`data/resource_index/series_latest_100_feed.json` 及其上游影视采集、解析、合并、导出流程
边界：本文只描述数据生产问题与验收标准；App 仅保留必要的展示兜底，不在本轮修改爬虫实现。

## P0-1：电视剧没有本地封面资产

### 现状证据

- 当前 100 条电视剧均有 `cover_source_url`。
- 当前 100 条电视剧均没有 `cover_asset_path`。
- App 只能临时使用远程封面并依赖系统缓存；离线、弱网或图片源失效时会退化为占位海报。

### 目标

数据生产侧在生成 Feed 时下载、校验并压缩电视剧封面，输出与电影一致的本地资产契约：

- `cover_asset_path`
- `cover_width`
- `cover_height`
- 内容哈希
- 本地文件真实存在

建议单张封面控制在约 30–80KB，优先 WebP/JPEG，最长边不超过 720px。App 运行时不应依赖资源站图片域名。

### 验收

- 100 条记录全部有安全相对路径。
- Feed 汇总满足 `cover_count == record_count == 100`。
- 构建后断网打开电视剧频道，列表和详情页均能显示真实封面。

## P0-2：资源标题丢失集数语义

### 现状证据

影片：`X战警97 第一季`
媒体 ID：`movie:9b2d76c3141ab99a5408f46a7bceb499ee6eb30c1082d9d86bc9a99f23cf6226`

Feed 中大量磁力资源的 `display_title` 都只是：

```text
1080P
```

但磁力 URL 的 `dn` 参数实际包含明确集数，例如：

```text
X-Men 97 S01E01 ... 1080p ...
X-Men 97 S01E04 ... 1080p ...
X-Men 97 S01E10 ... 1080p ...
```

因此集数信息在源数据里存在，是导出 `display_title` 时被丢弃，并非资源站没有提供。

### 目标

导出资源标题时按以下优先级取值：

1. 源站真实资源标题；
2. 磁力 `dn` 参数；
3. 文件名；
4. 最后才退化为清晰度标签。

建议输出：

```text
S01E01 · 1080P
S01E04 · 1080P
S01E10 · 1080P
```

建议新增资源级结构化字段：

- `season_number`
- `episode_start`
- `episode_end`
- `episode_label`

### 验收

- 当磁力 `dn` 中存在 `SxxExx`、`E01`、`第01集` 等模式时，`display_title` 不得只剩 `1080P/4K/HD`。
- 同一剧集中不同集数的标题必须可区分。
- 增加针对 `S01E01`、`S01E01-E02`、`第1-2集` 的自动测试。

## P0-3：第一季条目混入第二季资源

### 现状证据

`X战警97 第一季` 的资源集合中同时出现：

```text
S01E01
S01E10
S02E01
S02E03
S02E06
```

这说明当前合并身份只按系列名称聚合，未严格按季分桶，导致第一季详情页混入第二季资源。

### 目标

媒体身份至少包含：

```text
规范化系列名 + season_number
```

当资源可解析出季号时，必须与条目季号一致；无法判断季号的资源进入待审计集合，不得静默并入明确季条目。

### 验收

- `第一季` 条目不得包含 `S02Exx` 资源。
- 同一系列不同季应生成独立媒体条目或明确的季级资源分组。
- 增加“跨季资源不得错误合并”的反例测试。

## P0-4：电影类型与国家字段包含解析残片

### 现状证据

问题集中在电影 Feed：

```text
data/resource_index/sixv_app_bundle/feed.json
```

当前 50 部电影中检测到：

- 25 个异常类型值；
- 14 个异常国家地区值；
- 电视剧 Feed 当前没有命中同类异常，但必须共用同一数据质量门禁。

真实异常示例：

```text
: 喜剧
: 剧情
惊悚 片"> 惊悚
纪录 片
: 美国
: 中国 大陆
```

这说明详情页 HTML/文本解析后，没有在数据生产侧完成标签节点提取、HTML 残片剥离和规范化，导致展示层收到不可直接使用的分类值。

### 根因要求

不得只在 App 中修字符串。数据生产侧需要在解析和导出阶段统一完成：

1. 从正确的 DOM 节点或结构化字段提取类型、国家地区，不把标签周边 HTML 文本写入值；
2. 去除前导 `:`、`：`、分隔符和多余空白；
3. 清除 `<...>`、`">` 等 HTML 残片；
4. 统一同义和空白变体，例如 `纪录 片 -> 纪录片`；
5. 去重后再写入 `genres`、`countries`；
6. 原始值如需审计，应写入独立 `raw_*` 字段，不得污染面向 App 的规范字段。

建议数据侧提供统一函数：

```text
normalize_genre_label(raw)
normalize_country_label(raw)
```

该函数应在所有电影、电视剧来源的最终导出前强制执行，而不是只针对 SixV 打补丁。

### 验收

- `genres`、`countries` 中不得出现前导冒号、HTML 标签、`">`、异常尾部“ 片”或连续空白；
- 规范字段必须满足“单一纯文本分类值”，不得包含页面结构字符；
- `惊悚 片"> 惊悚` 必须归一为 `惊悚`；
- `纪录 片` 必须归一为 `纪录片`；
- `: 美国` 必须归一为 `美国`；
- `: 中国 大陆` 应按数据契约拆分或规范为可稳定匹配的国家地区值；
- 对电影和电视剧 Feed 同时运行质量门禁，异常数量必须为 0；
- 增加包含上述真实反例的自动测试，防止解析器升级后回归。

## P1-1：日本频道当前没有可用样本

### 现状证据

当前 100 条电视剧国家地区分布包括：

- 美国 46
- 中国 18
- 大陆 17
- 韩国 9
- 英国 9
- 其他若干
- 日本 0

App 会保留“日剧”频道，但当前离线快照会显示空频道提示。

### 目标与验收

- 增加稳定的日剧来源或补充现有来源覆盖。
- 下一版 100 条电视剧快照中至少包含可验证的日剧样本。
- 不允许仅根据语言、标题猜测国家地区；必须保留可追溯来源字段。

## P1-2：缺少真实排行榜或热度依据

### 现状证据

现有 Feed 只有抓取顺序、更新时间、更新状态、评分、地区和资源数量，没有播放量、站内热度或权威榜单排名。

### 产品约束

App 当前只展示“追更速递”和“最近更新”，不会把抓取顺序伪装成排行榜。

### 后续建议

如要增加“排行榜”，数据侧必须提供至少一种可审计依据：

- 来源站真实榜单名和排名；
- 多来源共同出现次数；
- 豆瓣/IMDb 评分与有效评分人数；
- 明确的热度计算公式与生成时间。

字段建议：

```text
ranking_type
ranking_name
ranking_position
ranking_score
ranking_evidence
ranking_generated_at
```

没有证据时不得输出“热播榜第 N 名”等误导性文案。

## App 临时兼容措施

在数据侧修复前，App 已采取以下临时措施：

1. `cover_asset_path` 缺失时使用 `cover_source_url` 并启用图片缓存；加载失败仍有本地占位海报。
2. 当资源标题只有 `1080P/4K/HD` 时，从磁力 `dn` 中提取 `SxxExx` 或中文集数，显示为 `S01E01 · 1080P`。
3. App 只做展示层补救，无法可靠修正跨季资源混入；跨季归属必须由数据生产侧修复。
4. App 临时清理类型和国家字段中的前导冒号、HTML 尾片及空白变体，并合并同义分类，避免脏数据直接污染频道和类型胶囊。
5. 上述展示清洗不是验收终点；数据侧修复后，Feed 原始规范字段本身必须通过 P0-4 的零异常门禁。
