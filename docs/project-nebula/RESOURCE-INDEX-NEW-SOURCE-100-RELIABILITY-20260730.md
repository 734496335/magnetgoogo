## DYTT可靠性重裁

### 原始问题

直接取DYTT最新100条时，大量旧记录只有失效FTP或播放器资源：

- 旧FTP域名在国内公开DNS下不可达；
- HLS播放流虽然可访问，但当前App资源协议只正式消费磁力和网盘；
- 源页还存在少量把其他影片FTP链接误挂到当前影片的情况。

因此“抓到100个页面”不能等同于“得到100条可靠资源”。

### 最终方案

DYTT改为：

```text
扫描最新250个候选
→ 保留原始候选与失败证据
→ 只选择标题、封面、磁力/网盘均合格的记录
→ 按最新顺序输出100条正式Feed
```

最终结果：

- 候选250；
- 详情成功249；
- 永久404候选1；
- 具备磁力/网盘的合格候选115；
- 正式Feed取最新100；
- 正式资源159个，全部为磁力；
- 非法磁力0；
- 重复info-hash 0；
- 跨影视重复资源0；
- 缺标题0；
- 缺封面0；
- 仅FTP/HLS等不适合正式发布的候选134条被排除。

分页分布证明扩大窗口不是盲目堆数量：第7、8页分别25/25合格，后续页面继续稳定提供磁力资源。

### 永久404与重试

DYTT明确HTTP 404现在映射为`NOT_FOUND`，一次即进入终态；连接错误、5xx和限流仍按原策略重试。这样不会每天对确定不存在的详情重复消耗预算。
